## 1. 使用方法与完成规则

1. 开始开发前读取[进度页](../development/PROGRESS.md)，找到当前任务，再阅读其阶段文件、设计依据与实际源码。
2. 选择依赖已完成的最小任务；把进度页当前任务设为该 ID。默认顺序执行，开发中允许在同一阶段选择不依赖其他未完成任务的项。
3. 对逻辑变化先写能揭示错误的用例，再实现并验证；不是每个文档/样式改动都要求新增测试。
4. 验证通过后保存 `docs/development/records/<任务ID>.md`，在本页勾选，并同步进度、变更和受影响的接口/配置/运行文档。
5. 一次会话结束时，即便未完成，也记录已修改文件、已执行检查、失败/阻塞原因与下一条具体动作。未验证任务保持未勾选。
6. 新需求先评估影响，保留原任务 ID，追加新 ID 和依赖；不删除失败记录或把历史状态改写成成功。
7. 按[阶段审查与授权](../development/REVIEW_STATUS.md)在获准阶段内连续开发；阶段末提交修改范围、验证和风险，由原规划会话独立审查后授权下一阶段。任务验收与总控审查分开记录。

共 **78 个任务**：76 个核心任务、2 个可选任务（M5-06, M6-06）。当前核心32/76、可选0/2；M2-09/10/11/12已通过第2轮总控复审，M0/M1/M2均通过，原记录和快照保留。授权M3-01至M3-11按依赖执行，阶段末审查，M4未授权，见[M2总控结论](../development/reviews/M2-review-r2.md)。计划文档完成不计入产品功能进度。不承诺总工期，按验收推进。

完成一个任务需同时满足：实现达到该项验收标准、相关验证已实际运行、记录可以复查、相关文档已同步。阶段最后一项为验收门槛，不以“代码写完”替代。可选项可以记录“延期/不采用”和理由，保持不勾选；最终报告分别统计核心完成率与可选范围。

## 2. 全局约束

- 只使用 Vue 3 前端，不引入 React；业务文案、配置说明和新增注释使用中文，必要版权/许可证原文保留。
- 当前优先 Windows 本机调试，基础设施与 Celery worker 使用 Docker Linux；Ubuntu 部署在 M7 验证。
- 不打印 `.env` 值，不将密钥放进日志、浏览器、研究记录或 Git；新增必填配置同步 `.env.example`、`docs/CONFIGURATION.md` 与缺项说明。
- 当前 86 份课程资料的历史入库记录保留；所有破坏性/故障/迁移验证使用明确的独立测试库、集合和对象前缀，不把当前线上数据作为测试沙箱。
- 迁移使用 v2 集合，旧集合保留；先 dry-run、小样、校验，再扩大；发布新指针前旧数据保持可服务。
- 不先升级模型来掩盖逻辑错误；默认策略变更要有基线、分题型对比和回滚配置。
- GitHub 源码复用记录固定 commit、文件映射、许可证与改动；assistant-ui Vue/MCP/Ragas 均不是首版必选依赖。
- Git目标为用户仓库 `https://github.com/gc10000/Zhi-Heng-Agent.git`。已授权首次接入和后续按任务提交/正常推送，无需每次确认；验证后同步源码/测试/文档，记录分支、SHA和推送结果。先核对远程历史，排除密钥/模型/课程原件/运行数据/本地备份，遵循[Git工作流](../development/GIT_WORKFLOW.md)。不强推覆盖或伪造历史；同步代码不改变阶段审查及部署授权。
- API/数据契约变更先记录兼容影响；审查记录中已发现的问题，只有回归通过后才更新为已修复。

| 变更类型 | 必须同步 |
| --- | --- |

| 技术或范围取舍 | DECISIONS 中追加理由、替代关系、受影响任务与回滚方式 |

| 数据结构/索引/发布迁移 | 知识 schema、迁移/回滚 runbook、映射统计与验收记录 |
| 复制或安装第三方源码 | THIRD_PARTY_NOTICES、复用 manifest、上游版本与修改摘要 |

| 评测策略/默认参数变化 | 题集/配置版本、实验记录、质量报告、回滚方式 |
| 部署和恢复变化 | 对应 Windows/Ubuntu runbook、配置拓扑、恢复/容量实测 |
