# M6 已封存审阅偏差与适用性冲突的总控处理决定 r1

2026-10-30。审查对象c9d115e，适用现有assistant-development-v1／question-purpose-v1开发验收。此记录解释既有题意规则并授权受控证据修复的实现范围，不修改两份已批准政策文档、已登记政策hash、题集／manifest／配置或结果；不是新评分或独立性attestation。本轮没有写真实审核、校准、候选或proof。

## 独立性裁定

1. 两版本第一轮审核者均实际接触过001的expected、allowed_evidence和旧annotation。第二版相同执行上下文保留这一暴露，因此两版001的第一轮不满足无旧判断输入的要求。声明之后未用标签打分不足以消除已知输入。不为现有完整两轮签署attestation；不据此宣告其余84题均被污染。
2. 两轮分别由不同任务执行，正式开始／封存顺序及完整结果来源匹配。跨版本沿用各自上下文、同模型／同登记账号本身不等于轮间复制；未见第二轮读另一轮评分或补正的证据。第二版第一轮继承001暴露按上一项处置，其余不扩大。
3. 第二版第二轮只读取第一轮begin回执字节并计算SHA。已核回执仅含id、sha256、created_at、execution_id、reviewer_model，不包含题级判断／评分；保留违反本包严格目录隔离约束的事实，限定裁定为流程偏差，现有证据不足以认定第二轮读过第一轮评分。不因该偏差要求全量重审。下包输入清单由协调侧提供，审核者不进入另一轮目录，连hash检查也由协调侧完成。
4. exact provider model ID未知不造值，也不新增必须不同模型门槛。来源清单、时间与真实任务声明支持部分独立性结论，但没有可独立重放的完整平台消息／访问轨迹；对未访问内容的判断依赖封存provenance，报告保留限制。本次不把审阅哈希核对称作340条语义再评分。

## 适用性解释冻结

先按用户问题要求的交付物判断，不按回答有没有步骤判断。要求参数、配件／接口、兼容范围、能力有无、风险提醒内容或安装前提的识别，可为N/A；要求实际配置、检查／验证、排查或安全处置，则适用。单个观察动作或“停止自行拆换并交服务中心”的处置也可能充分，不强制多步骤。N/A不是2分，适用后仍需独立判0／1／2／unknown；不能因这次裁定预填高分。

## 为什么现有接口不能直接续写

DevelopmentPolicy.begin以[experiment_id,round]固定唯一身份；seal要求整份85题，scope还绑定完整题集结果。第三轮不在schema内。现有resolve只接受原审核者的全部unknown；确定的N/A或数值不能借追加改写。ReviewService._quality在所有维度拒绝N/A与数值混用。没有合法的部分修复／替代对／适用性裁决接口。

因此禁止覆盖原评分、删除封存、手改reviewer／round／subject、把unknown伪填回旧记录、另换ID当独立执行、复制第二轮冒充第一轮、创建新答案实验掩盖审核问题，或把N/A折成0／2。也不能以第三票多数、平均分或客户端passed解决。
