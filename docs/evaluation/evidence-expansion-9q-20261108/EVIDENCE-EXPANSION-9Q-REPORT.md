## 三、定性对比（关键题）

**support-v1-019（CB304n 连通性确认，troubleshooting）——扩展的正向案例**
- off（765字）：3 步（连接→IP→确认），但无线连接只说"通过无线方式连接"。
- on（1141字）：同样 3 步，但补全了**无线 SSID 细节**（"ROUTE_XXXXXX，XXXXXX 为设备背面铭牌 MAC 后六位，该网络不加密"）与双引用支撑 [2][13]——这正是父块扩展把被切断的相邻说明块带回上下文的直接证据。**操作前提完整性明显提升**。

**support-v1-003（拨号控制列表，configuration）——诚实性提升案例**
- off（189字）：仅找到章节标题，拒答。
- on（328字）：多带回 `dialer number` 命令说明块（"用来配置发起呼叫的拨号串"）[2]，仍拒答具体配置但**说明了缺什么**，拒答质量更高。

**support-v1-001（互通性，parameter）**
- 两轮结论一致（qwen3.8-flash 时代基线答案亦如此），on 轮引用从 10→14，概述章节的相邻块补入。答案长度基本持平（268→275）——**参数类问题扩展不改变结论，只增加支撑**。

## 五、过程事件与限制（如实）

1. **环境抖动**：实测期间 Windows 宿主内存临界（0.2-1.9GB 波动）引发 Docker 内部 DNS 间歇失败，off 轮与 on 轮各报废过一次（每题随机 interrupted）。处置：停旧预览重栈（zh-m7-05d09f 7 容器）与开发栈备份源（5 容器）腾内存，重启 api 清坏连接池后，两轮在干净窗口 6-12 分钟完成。**有效数据均在稳定窗口采集，不受抖动污染**（无效 run 均为 interrupted/error 已剔除）。
2. **模型名迁移**：`.env` 注释里的 `qwen3.8-flash` 已在百炼下线（Model not exist），实测改用 **qwen3.7-plus**（182 个在列模型实测可用）。后续应同步更新 .env.example 与文档。
3. **单轮无重复**：每相位每题只跑 1 次（LLM 生成有随机性，严格结论需多轮均值；本次为产品化判定的最小证据集，符合 A.1"最小证据集"定义）。
4. **耗时观察**：on 轮单题 30-60s 与 off 轮稳定窗口（30-60s）相当，未观察到明显的输入预算压力导致的延迟恶化。
5. **restore 链路顺带验证**：官方 backup→restore 工具链全程可用（manifest 指纹校验、三重防覆盖锁、失败预留需人工清理——本次演练了完整故障路径）。
