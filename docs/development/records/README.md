# 任务验收与交接记录

每个任务建立 `<任务ID>.md`；开发中的失败和中断也记录在同一文件，最终追加通过结果，不删除历史。`PLAN-01.md` 仅验证计划文档，不代表功能完成。

每份业务记录必须包含以下字段：

| 字段 | 内容要求 |
| --- | --- |
| 任务与日期 | 固定 ID、计划链接、实际执行日期 |
| 状态 | 进行中/阻塞/已验收/延期；明确是否允许勾选 |
| 目标与文件 | 本次实际实现行为、改动文件、与计划的偏差 |
| 环境 | OS、Python/Node、相关依赖、测试数据命名空间；无凭据 |
| 验证 | 精确命令、退出码、通过/失败数、输出或截图路径 |
| 对照 | 缺陷修复的前后行为；新能力的成功/失败/权限路径 |
| 数据与配置 | 实际读写范围、必填/可选配置项名称及检查结果 |
| 文档同步 | 总清单、进度、变更及受影响接口/配置/复用文档 |
| 遗留与回滚 | 未验证内容、兼容影响、撤回方式、下一条动作 |

通过的标准：每个验收条件都有实际证据。跳过测试、缺凭据、只有 mock 界面或沿用旧截图，均不能证明真实链路已通过。仅适用于纯逻辑的单元测试无需云服务；不要为了凑证据增加无关调用。
