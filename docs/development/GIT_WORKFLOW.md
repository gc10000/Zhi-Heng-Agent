## 首次接入

1. 检查 Git 根目录、工作区、分支和远程。2026-10-23 本次文档更新时确认项目尚未属于 Git 仓库；执行时以最新实际状态为准。
2. 若仍未初始化，允许在 `Product-Knowledge-Rag` 目录建立仓库，不纳入父目录及相邻课程项目。已有仓库则复用，不重复初始化或覆盖远程。
3. 以不含凭据的地址绑定 `origin`，核对远程默认分支与提交。远程非空先 fetch、检查历史，保留 README/许可证等远程内容后正常整合；不强推覆盖。已有不同 origin 时先核对用途，不直接改写。
4. 审阅 `.gitignore` 和候选文件。首次提交记录当前已验收 M0 基线，说明课程底座和独立修复，不伪造此前逐项提交历史。基线与后续 M1 变更分开；已混入M1且无法可靠分离时如实记录，不回退用户改动来凑基线。
5. 首次沿用远程默认分支，空仓库可用 `main`；已有合理工作分支则沿用并设置 upstream。正常 push 后核对远程分支头与本地 SHA。身份/认证缺失时报告需配置的项目，保留本地工作并继续可执行开发，不把未推送写成已同步。

## 文件范围

- 提交业务源码、测试、依赖清单/锁文件、Docker/部署定义、`.env.example`、开发文档与已脱敏且必要的验收证据。
- 排除 `.env`、凭据/私钥、模型权重、虚拟环境、课程原始 PDF/Excel、解析缓存、数据库/对象存储数据卷、运行日志和临时输出。
- 单独审阅 `docs/development/evidence`，目录名不代表内容适合上传。`originals`、`r2-before`、`r3-before` 等本地备份不默认提交；真实报告中的内部路径、对象URL和配置须核对。必要时生成明确标注的脱敏副本，保留本地原证据，不手改历史输出冒充原件。
- 前端建立后同步忽略 `node_modules`、构建输出和工具缓存；忽略规则不会移除已跟踪文件，仍须检查暂存内容。
- 保留课程及复用源码的来源、版权与许可证，个人贡献按实际改造说明，不将来源代码写成全部原创。

## 每次更新

1. 开始任务前检查 status、diff 和分支。远程更新先 fetch 检查，避免有未提交改动时盲目 pull/rebase，不覆盖或清理用户工作区。
2. 按任务或内聚修复形成小提交，源码、必要测试与文档一起提交；先完成相称验证、审阅暂存差异及文件清单。不无审阅地 `git add .`。
3. 提交信息包含任务ID和中文说明，如 `feat(M1-01): 定义知识实体与稳定标识`、`fix(M1-07): 保留表格来源范围`。失败实验不写成已通过能力。
4. 任务验收后正常 push 到已核对分支；有意义的中途接续点可提交并注明未完成。代码同步不代表阶段通过，阶段末仍交总控审查。
5. 进度、任务交接与审查材料记录分支、已完成提交SHA、验证与推送结果；自身提交SHA可在后续交接或最终回复补记，不反复amend以包含自身SHA。区分已提交、已推送与未提交范围。

认证/网络失败或远程分歧如实记录，不输出令牌，不删除远程分支，不用强推、破坏性reset或重写已推送历史来绕过。必要时报告用户需配置的缺项，其余授权开发继续执行。
