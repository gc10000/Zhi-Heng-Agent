## ADR-016 · R3 历史JPEG元数据兼容与真实验收 · 2026-10-23

原图片题成功续验后，准确JPEG真实HTTP200/hash/解码均符合预期，但既有对象Content-Type为image/jpg，验收器与Pillow标准image/jpeg比较失败。选择仅将image/jpg归一为image/jpeg，再验证实际格式；不接受任意image/*互换。先红测1 failed/19 passed，修复并增加PNG伪装反例后21 passed。替代方案是修改对象元数据或再次推理，前者触及受保护数据且非必要，后者重复费用/写历史；因此用已保存助手正文SHA256唯一匹配原响应，核对原final图集合，再真实HTTP只读复核。共享检查条件全部保留，PNG冒充JPEG仍拒绝。

另起正常配置新进程，无诊断预热/线程覆盖，首次查询实际加载模型、调用图/仓储/云模型并检验唯一final与一次助手保存；只覆盖隔离数据名、日志关闭与禁止模型下载。一次成功满足本次冷启动验收，不解释为所有历史原生崩溃已根治或长期稳定。原43.085秒图片异常未复现，脱敏诊断包装未捕到新异常，不能倒推旧根因。影响M0-09、验收共享函数、2项测试、新复核/冷启动脚本与文档，无生产逻辑/依赖/配置变更。证据与精确命令见records/M0-09.md；回滚逐片对照r3-before，停用新脚本即可，不删数据。替代ADR-013/015中“待恢复待真实验收”的当前状态，保留其历史事实。

## ADR-015 · R2 准确图片验收与 N2 新快照 · 2026-10-23

旧前缀/非空200可能接受HTML或错误图，选用“人工确认图1 SHA256 + 复制清单准确origin/bucket/key + 无重定向HTTP + MIME/hash/解码 + 正文/final关联”共享检查，两个真实脚本共用，避免判断分叉。允许final额外包含已记录合法图，但必须含正确拓扑；未知URL下载前拒绝。额外成本是逐图下载/解码，仅用于小样验收。已目视完整手册第4页/节选第1页和缓存图，HTTP仍待Docker恢复。纯离线反例10失败后修复19通过，无依赖安装。继承前轮两题成功，不把Docker故障当原图片异常根因。

## ADR-010 · 旧 API 终态归外层 · 2026-10-22

输出节点仅返回生成结果，外层在整图正常返回后发送唯一 final，失败保存 partial_answer 而非成功 answer。相比节点先发成功再外层更新状态，避免客户端观察到相互矛盾终态；旧非流式失败 HTTP 502，供客户端区分失败。仅修旧进程内协议，不提前实现 M2。证据 M0-07，回滚恢复对应片段。


## ADR-011 · provider 能力与日志基线 · 2026-10-22

auto 按精确主机/百炼子域识别，代理需显式 dashscope；通用兼容接口不传 enable_thinking，保持当前百炼默认 false。缓存按有效配置分隔。日志移除输出 prompt、图片和 MinerU 签名链接，关闭 diagnose 局部变量展开；避免仅降 INFO 后 DEBUG 仍泄漏。证据 M0-08。配置可回退，未升级模型、未改 .env、未清理旧日志。


## ADR-012 · M0-09 真实验收发现设备参数偏差 · 2026-10-22

两次整图真实验证在加载重排时 torch_cpu.dll 原生崩溃（0xc0000005）。只读张量探针与独立 CPU FlagReranker 加载/打分均成功。源码核对 SDK 1.3.5 接收 devices，旧封装传 device 被 kwargs 吞掉，实际默认选 GPU，违背 BGE_RERANKER_DEVICE=cpu。最小调整为 devices，不升级模型或依赖；通过先失败后修复的构造回归验证。串行预热仅在验证脚本作为诊断措施，独立记录，不能将其解释为默认无预热已验证。若仍失败保留 M0-09 未完成。证据 M0-09-reranker-*。回滚该单词级参数修复不会改变模型文件。
