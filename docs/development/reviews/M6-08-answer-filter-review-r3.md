## 接续路线纠正：回归题草稿与资料修订不能混用

源码`app/evaluation/feedback_triage.py::bind_revision()`在任何资源访问前要求`draft.kind == 'revision'`；对confirmed regression返回`409 revision_draft_required`。前端`FeedbackQueue.vue`也仅为revision分支显示绑定表单。`save_quality_proof()`的affected/full证明绑定validated目标修订，属于资料发布路径。

因此，[本轮执行报告](M6-08-execution-continuation-r1.md)中M6-05矩阵及“先给既有regression草稿绑定修订”的统一接续说法不适用。此前总控交接Prompt也引入了这项错误依赖，本轮纠正；历史记录不覆盖、不改写既有草稿类型。

- **回归题路径**：保留真实反馈与regression草稿，核实草稿如何经标注审阅进入版本化dev回归范围、如何绑定反馈后运行及复评证据。尚无证据证明该路径已经完整接通；执行端先依据现有标注流程核实缺口，不能假装已有revision绑定或证明。不得自动污染冻结题集、复制heldout、改写旧草稿或捏造反馈。
- **资料修订路径**：仅在真实反馈确实要求资料修订且形成对应revision草稿时，才绑定目标修订和受影响题，执行affected→full质量证明及正式发布门禁。不为绕过regression路径凭空创建修订。
- **正式人工门槛**：当前human双轮/预校准规则仍有效，未改为助手评分；技术诊断、助手判断和回归路线核实可以先推进。不得再把所有未完成工作概括为等待用户做85题。
