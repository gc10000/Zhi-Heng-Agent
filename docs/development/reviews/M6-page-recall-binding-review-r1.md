## C06-PAGE-R1-R / P2：页内独立子串不能证明完整表行

位置：`app/ingestion/parsers/table_sources.py:22` 至33，核心为27行 `all(cell in pages[page-1] for cell in cells)`。全页归一去空白后，对各单元格分别做子串查找；唯一页及连续页序只能限制页范围，不能证明型号词完整，也不能证明限定与说明属于同一行。

本轮两个独立反例都通过 **正式 MineruParser→chunk_document** 复现，不调用解析模型：

1. 原件只有 `AX2400 Supports wired network connection`，缓存表行为 `AX240 | Supports wired network connection`。当前保存精确p1，既不标未知，也不触发`table_row_page_unresolved`；AX240被当成AX2400子串。
2. 原件p1分两行：`2014 Legacy wireless only`、`2019 Supports wired network connection`，缓存行为 `2014 | Supports wired network connection`。当前仍标精确p1，短版本和长说明各自在页中出现便被拼成完整行证据。

期望：无法证明完整词和限定/描述的关联时保存未知，不授予精确定位。第二例在缺少可靠行/区域信息时应降低精度，不能通过仅增加单词边界解决。连续跨页单元格分支采用同样的独立子串条件，须一起补齐。无需强制采用某个新库或以模糊匹配强行减少未知。

本问题是精度声明错误，不意味着已经证明本批136行中有同样错行，也不否定已直接核对的microSD/RJ45原件页。执行方须将两反例原样纳入回归，再对已标精确行复核同类风险；对不能证明的行回退未知。新算法/数据使用新修订和指纹，保留本批及旧582/867历史证据，不手改历史结果。
