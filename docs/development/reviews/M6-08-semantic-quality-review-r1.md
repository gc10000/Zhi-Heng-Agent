## SQ-R1 / P1：生成投影将有效命令、公式和跨行代码误当图标改写

位置：`app/answering/context_budget.py:13`、`:20`；全局生成入口在第31行对每份证据调用该投影。

`prose()`对任意连续大于号及全部`\emptyset`/`\varnothing`做替换，未要求存在已确认的缺图标导航结构；行内代码保护正则又禁止跨行。结果是有效技术正文被送给模型前改写，尽管原引用/`prompt_used_docs`仍保留原文。

独立反例使用合成PDF、正式MineruParser读取无围栏`code_body`，经正式chunk_document及`step_2_construct_prompt`：原命令`echo diagnostic >> trace.log`在解析、切片、引用中完整，最终prompt却变成`echo diagnostic 〔未识别图标路径〕trace.log`。另两例为数学空集符号、CommonMark允许的跨行行内代码，均被替换。调用修复前fc386681的原打包器时，三例均保持原文；这是本次引入的语义退化。

影响：模型接到的依据与原引用不同，诊断重定向、表达式或集合定义可能失真。只保证证据存储未改，不能证明模型实际读取的内容未改。

要求：只对有明确来源及结构依据的缺失UI图标做可读标注，不能把合法操作符和数学记号全局归类为图标。保护正式解析入口接收的无围栏代码和合法跨行代码跨度。保留已确认缺图标导航的显式缺失提示、原引用及预算计量；不得用固定命令或题号白名单规避。补回归验证实际prompt，而非只检查原始doc对象。

## SQ-R2 / P2：代码围栏识别没有匹配开闭长度，仍会切碎有效代码块

位置：`app/ingestion/stages/chunking.py:69`。

新增正则把任意至少三个同类符号当结束围栏，没有约束其长度不少于开围栏。独立反例以四反引号包住含三反引号的代码示例，整个合法块长146字符，上限80：应明确报单块超限，实际被切成80和66字符两片。内部三反引号被误当作结束边界，绕过了原子性检查。

影响：代码块后半段可独立索引、单独召回，缺少开围栏或完整命令上下文。本项是本次CLI原子保留修复的覆盖缺口；修复前分割器也没有相应原子保证，不误记为新出现的旧代码行为退化。

要求：按真实Markdown围栏规则识别同类符号与长度，原子保留整个代码块；有效单块超限时显式失败。补充反引号、波浪线、较短内部围栏及正式chunk_document入口用例；保留其他正文/图片表达式边界。可使用已固定的Markdown解析依赖，不能继续以不完整边界正则宣称通用代码块完整性。

## SQ-R3 / P2：有表头的两列表被当作无表头，版本条件与数据行分离

位置：`app/ingestion/stages/chunking.py:36`到`:42`；`_TableReader`只登记th，没有登记thead的显式表头结构。

影响：即使全文中每个单元格都还存在、1360项字符保留检查通过，单独召回数据片仍可能把旧版本限制泛化。字符存在检查不能替代表格语义完整性。

要求：识别显式表头结构，表头中的单位、对象和版本限定必须随对应数据片保留；不能只靠几个完全相等的列名判断无表头。保留真正无表头部件表逐行索引的收益，补齐thead/td、带单位或限定词表头与无表头对照回归，并核对本机四文档新旧表格输出差异。不要求用户重查原PDF。
