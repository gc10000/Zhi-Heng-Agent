## AF-R1／P2：表格单元格跨度被扩大到整行

位置：`app/runs/answer_filter.py:19–24`，后续图片跳过分支在89–92行。`inline` token的`map`是行坐标，表格各单元格共享行范围。实现重新对整行识别反引号，可能把两个单元格各自未配对的反引号拼成一个代码跨度。

合成输入（允许资产仅为`diagram`）：

```markdown
| A | B |
|---|---|
| `x | ![bad](asset://other)` |
```

正式展示端采用的Markdown语法将第二格识别为图片；当前后端输出却原样保留未登记的`asset://other`，因为把该位置误判为代码。整串、逐字符及诊断中的多种分段均可复现；旧过滤器会输出拒绝占位。该缺口也使允许资产的规范化分支被跳过。

整改要求：按真实行内容器及原文坐标判断代码，不能跨表格单元格配对分隔符；用合成表格验证未登记图拒绝、登记图规范化、合法单元格代码原样保留。不得因此改动已关闭的语料SQ实现或放松资产授权。

## AF-R2／P2：未完整围栏起始行提前放行，输出依赖流分段

位置：`app/runs/answer_filter.py:67–73`，尖括号同类提前输出分支在47–53行。围栏起始行尚未结束时，被临时解析为代码块并已输出内容；后续同一行出现反引号使其不再是合法围栏，已发送内容无法重新过滤。

精确合成分段使用以下Python字面量，避免把单个尾反引号误读成有效关闭围栏：

```python
first = '```x ![image](asset://other)'
last = '`\n'
```

同一完整文本一次输入，输出为`三反引号x （图片未在授权来源中登记）单反引号`及换行；分为上述两片或逐字符输入，未登记图片原样保留。完整文本在正式Markdown语法下是含图片的普通段落。旧过滤器在这三种分段下均拒绝该图片。

整改要求：围栏起始行的解释尚可被后续字符改变时，不提前做不可撤回的代码放行；保留合法围栏流式输出能力。回归须比较整串、关键分割和逐字符的最终输出一致性，同时覆盖合法长围栏及真正代码内图片示例。
