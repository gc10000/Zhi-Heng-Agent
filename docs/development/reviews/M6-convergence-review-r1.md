## 剩余技术项（本次完整失败列表）

### C09／P1：摘要隔离与来源前提组合在正式 QueryRunner 入口被拒绝

位置：`app/runs/query_runner.py:137` 的配置相等判断，尤其139行；关联本轮新增 `RetrievalPolicy.exclude_image_descriptions`。

来源前提开启时，正式消费者要求整个 RetrievalPolicy 等于旧默认。新过滤开关设 true，即使仍为 weighted、原预算、原隔离范围，也不等于默认，因此在 authorization 阶段直接 failed／provider_invalid_response／retryable=false。成对独立探针使用正式 QueryRunner 和 InternalRunInput：关闭过滤时 completed、前提读取1次、合成答案1次；启用过滤时 failed、前提读取0、合成答案0。没有供应商调用，也未修改真实 Run。

影响是本轮拟冻结的“weighted＋来源前提＋摘要隔离”无法通过正式入口执行。22/25 证据来自实际索引与组件级重排/前提/prompt组装，并不能证明此正式组合可运行。P1按当前拟运行路径被整体阻断记录；不表示默认路径已经退化，也不重开旧来源前提或图片协议关闭结论。

补修只放行明确审核过的过滤布尔变体，同时保持 weighted、候选数、上下文预算、隔离授权和身份冻结，不删除整个策略限制。纳入前提/过滤各开关组合、非授权参数拒绝、请求/Run配置差异及关闭回切的正式消费者测试。使用保存检索结果和合成响应即可，无需供应商调用。

### C03／RGL-R3／P2：完成 Run 尚未保存 outcome 时，恢复可追认变化后的输入

位置：`app/evaluation/query_adapter.py:245` 至首次冻结路径（关联253/271行），`app/evaluation/execution_links.py:55` 及 `app/evaluation/execution_identity.py:42`。

两路均复用同一目标 Run，没有新增合成答案调用；两条 Run/两次合成答案包含夹具的来源基线和本次任务，不是每次恢复新增2次。该反例证明存在原执行 link 可比时仍遗漏输入漂移校验；不声称在没有任何输出快照时能检测所有历史输出变化。

补修须在复用已完成/awaiting_input Run 首次冻结 outcome 前，核验原执行的正式 link 与原输入 hash。不能用新 attempt 刚计算的 hash 为自身背书，不能覆盖旧 link。已有 outcome 的完整结果变化拒绝规则继续保留；无变化的合法退出应复用而非一律失败。覆盖完成/澄清、同库/分库、输入及历史变化/未变、link缺失/不匹配、outcome前/后退出、累计/新增计量。所有故障操作限随机测试库。
