# M6来源约束比较回答设计

状态：经当前总控独立审阅，方向可行；已收紧比较目标与分类合同，进入实现计划。此状态只批准零调用实现计划，不代表代码验收、真实答案质量或新模型调用授权。

日期：2026-11-02。范围来自M6-048已保存输入与独立裁定；不构成新模型调用授权、阶段验收或真实质量证明。

## 用户问题与目标

048面向产品用户，原问题是：“LA2608与CB304n的上联方式相同吗？请分别引用资料比较。”用户需要直接、完整、带引用的自然语言答复，不应看到内部JSON，也不应被迫自行从原文中完成比较。

已审失败表明，必要正文已进入输入，错误发生在生成阶段的关系组织：用户访问CB304n、CB304n的Cable/同轴条件检查、LA2608到无线控制器的管理连接被放到了相同的“上联”比较层。原句摘录协议无法给出比较结论；继续修摘录协议不能达到本设计目标。

目标行为：先明确能否比较；分别描述每台设备资料实际支持的关系、用途和条件；只在同一语义层级且双方都有支持证据时比较介质或端点；缺任一侧证据时明确说明缺项及比较限制。不得把访问设备Web页面推成同轴的用途，不得把管理链路、客户端接入或排障检查改写成设备上联，不得把检查条件写成已成功链路。

## 选定架构

保留`assertion_binding_v1`作为原文摘录能力。新建独立、默认关闭的比较回答路径，不改变旧Run、旧proof、旧默认或旧输出身份。新路径从冻结输入及`source_relations`已产生的原句帧建立候选索引；模型只能选择帧编号，不能输出关系类别、端点、介质、用途、比较结论或自由文本。程序从被选原句帧重新派生事实、分类、同层比较和自然语言答案；内部选择与proof只供运行及评测使用。

本设计不采用“自由文本答案后做事后审查”：自由段落难以可靠定位每个关系断言及其来源，且旧048已证明只给模型区分要求不够。本设计也不采用让模型自报语义类别再由引用hash背书：跨度匹配只能证明文字来自资料，不能证明它是上联、管理链路或客户端访问。新路径让模型只承担资料选择；关系语义采用有版本的保守程序规则，未被规则明确识别的事实保留为unknown。

## 事实与来源结构

比较目标由查询规划器从用户原问题中确定并写入`QueryPlan`，不得从检索结果或模型选择倒推。首版只支持明确的`device_uplink`比较目标；客户端访问、管理链路和排障检查可作为解释性事实，不是该比较目标。目标未被明确识别或存在多个比较方面时，不调用比较选择模型，也不静默回退旧自由答案，而由程序请求用户说明比较方面。为避免改变旧Run、缓存和评测身份，QueryPlan字段缺省时沿旧序列化形态省略；仅新策略启用时显式写入Run、检查点和评测执行身份。

模型只可返回严格版本化JSON，内容限于本Run原句帧的唯一编号列表，schema标识固定为`comparison_frame_selection_v1`。模型不能提供或覆盖原子事实的字段。每个程序派生事实绑定：冻结产品身份、原句帧编号及hash、关系类别、方向与端点、介质、用途、条件／否定／版本范围及来源引用。引用必须来自本Run实际prompt-used文档，且一条事实只可归属一个冻结产品；不同原句帧不得拼成一条事实。用户答案引用对应完整原句，不把程序内部帧字段当成原文断言。

关系类别固定为`client_access`、`device_uplink`、`management_link`、`diagnostic_check`及`unknown`。类别表示资料在描述什么，不表示设备现场状态。首版分类合同如下，验证器必须从冻结帧和同一原句重算，不信任模型标签：`physical_check`帧只映射为`diagnostic_check`且保持条件状态；`access`／`login`只有在现有帧明确表达访问对象时才可映射为`client_access`；`service`只有在用途原文明确记载管理且端点完整时才可映射为`management_link`；`connection`若用途原文明确记载管理且端点完整，归为`management_link`；否则只有在同一原句明确使用“上联”或其固定英文等价词、发起端明确为该产品且介质与目的端完整时才可映射为`device_uplink`。发起端归属必须来自该帧冻结的产品成员映射；同一来源含多个产品且原句未明确点名时不得绑定。`unresolved`、泛称“连接”、缺端点、跨句补全或含否定／条件且无法按本版本合同安全保留的帧均为`unknown`。不得把`diagnostic_check`作为链路状态或上联能力参加比较。

程序对每个被选帧核对编号、产品ID、document/revision及原件身份、原文跨度坐标和hash、prompt-used载荷hash、否定／条件／版本范围，以及派生事实集合与答案proof的身份。跨度坐标采用已冻结原文字符串的Unicode码点索引；hash仍按现有规范计算。任何改写、跨修订、来源漂移、非法编号或无效跨度都拒绝形成成功结果。

机械一致性不等于语义蕴含证明。分类代码必须限制在上述可审阅合同内，并逐条绑定决定分类的原文字面证据及来源帧；不能用模型置信分数或引用跨度hash代替分类依据。目标层级不能从标题、邻句、产品型号、其他产品引用或一般网络知识补齐。无法依合同确定类别时降为`unknown`并阻止该事实参与强比较；扩大词汇或关系规则须单独版本化、加反例并经独立复核，不可在真实调用中临时补词。

## 比较与答案呈现

比较器只接收通过冻结来源核验及分类合同的事实，且目标必须是`QueryPlan.comparison_target=device_uplink`。双方必须各有一条明确上联帧及介质。首版介质映射固定为：`以太网`／`Ethernet`→`ethernet`，`同轴`／`coaxial`→`coaxial`，`光纤`／`fiber`→`fiber`；英文项仅忽略大小写和首尾空格。只有双方介质映射到同一规范值或两个不同的规范值时，才可判相同或不同；未登记词项、复合／含混介质或只知一侧均为`insufficient_comparison`。首版不做向量相似、模型同义词判断或开放式语义归一。两侧关系层级不一致时报告层级差异及缺失上联证据，不把类别不同写成设备能力不同。其他比较目标在后续独立设计和版本中处理。

程序按固定顺序生成自然语言：直接回答比较是否成立；分别给出双方有证据的关系描述；给出依据及其语义边界；若不足，具体指出缺失的产品、关系层或属性。引用贴在它实际支持的分句之后。完整被选原句可作为引用支撑，但不得代替比较句。用户端不显示JSON、分类标签、置信度、prompt或调试信息。目标明确但资料缺项时说明缺项，不要求用户重复选择产品；目标本身未能唯一识别时才请求澄清比较方面。

048的验收样例应表达：现有证据不能据此认定LA2608与CB304n的设备上联方式相同或不同；LA2608资料描述的是到无线控制器的管理连接，CB304n已保存材料描述的是用户访问及Cable/同轴相关内容，不能把这些层级拼成CB304n设备上联。各事实需引用其实际来源。该样例只定义语义验收，不是已生成的正式产品答案或新增评分门槛；EoC与GM/GU文字仍按已有收窄裁定，不新增普遍必答要求。

## 失败与身份

输入来源校验必须发生在模型调用之前。结构可解析且引用/来源身份有效，但关系层未知或比较字段不足时，这是有效的资料不足状态：比较器输出`insufficient_comparison`，渲染器给用户说明已知事实及缺项。JSON非法、超长、截断、引用越界、跨度不符或冻结来源校验失败属于协议/完整性错误：不向用户流式泄漏结构JSON，不回退到自由文本，不自动重复抽取，按受控失败结束。不得把协议错误伪装为资料不足，也不得把资料不足伪装为成功比较。

Run/outcome proof须绑定新模式函数版本、schema版本、冻结归属策略hash、完整prompt-used载荷身份、模型结构化事实hash、验证器版本、比较器版本、渲染器版本、最终答案hash及引用映射hash。缓存复用和恢复按同一完整身份重算验证；旧策略和旧Run不升级。默认关闭，不改公开API；新策略配置面、持久字段、失败结算和投影兼容性由实现计划明确并测试。
