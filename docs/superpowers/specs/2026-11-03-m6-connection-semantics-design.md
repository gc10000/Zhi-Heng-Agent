# M6连接语义消费与完整比较合同

日期：2026-11-03。基线`9024aad31451956faf2e177f4b7a530f5a6c0de2`。当前总控依用户既有授权自行审阅、取舍并批准零调用实现计划；未实现新业务路径，不构成独立技术验收、正式候选质量通过或新调用授权。旧设计及其失败保留。

## 产品目标与新发现

用户需要知道两台设备资料记载的上联/对外接入方式有什么区别，并看到各自依据。最终答复须直接比较，逐产品解释端点、介质、用途和适用条件；不能要求用户自己从摘录完成比较，也不能把客户端访问、管理用途和现场状态合成同一关系。

本轮对r8保存输入的只读审计确认两个独立问题：旧v3用互斥类别把排障条目的物理路径排除出全部比较，且比较介质不含3G/4G；r8的10份实际输入另缺产品概述中的Cable与无线路由器融合描述。该段在同一冻结修订物理第8页，原解析缓存hash匹配；一次限定资料/修订的业务query找到唯一正式切片，完整payload hash与原快照一致。没有重新核全量向量、默认指针或TTL。

后一发现仅适用于本次r8输入，不将2026-11-01独立确认的生成关系拼接错误改判为漏召回；不得据此整体重开检索、角色抽取或已关闭协议。只补概述的离线对照仍被旧v3判不足，证明补输入不是语义修复的替代品。

## 方案选择

| 方案 | 结果与取舍 |
| --- | --- |
| **采用：有来源的多维事实、限定属性比较、生成前来源依赖装配** | 将话语形式与连接角色分开，保留用途/状态；可明确展示比较依据和推导边界。新增规则须通过反例及独立复核 |
| 再加一版摘录模板或只扩介质词表 | 无法补足原文依赖，也无法纠正互斥分类造成的表达限制，不采用 |
| 自由答案后再让模型打语义标签或审核 | hash不能证明标签蕴含，额外调用也不能替代验证；本包不采用 |

不把模型标签、人工为048编写的事实卡、评分allowed_evidence或expected字段作为生产输入。当前私有草案只是总控设计例子，不是实现能力或评分结果。

## 来源依赖装配

本合同中的依赖是原资料片段，不是答案标签。为本轮问题补齐同一冻结修订的产品概述；未来程序按产品/资料结构选择，禁止按question_id、具体型号或rubric分支硬编码。本轮离线审计先保留原10项、追加唯一概述为第11项，以便比较，**这11项不是可执行正式配置**，不宣称符合原`context_limit=10`。

实现时新增内部`comparison_context`装配单元，仅在新模式启用时工作：从显式授权且逐payload核验的来源池中，对请求的每个产品保留已选连接证据、完整条件段，以及可唯一定位的产品介绍段。介绍段仅接受冻结来源heading_path末级完整标题匹配`产品简介`、`产品概述`或`概述`，可去掉标题前的章节数字；同一修订存在多个不一致候选或标题无法定位时，记录不确定，不能猜选。完整标题层级和跨度保留，不改旧抽帧或给原语料补角色标签。

资料装配按产品请求顺序、来源顺序和ordinal稳定排列，按chunk_uid去重。必要依赖先占用现有来源预算，再保留既有相关项；未被作为事实或完整条件使用的纯封面/版权项可在候选构造时被移出。必须同时遵守冻结context_limit、字符/token预算，不静默加到11项、不切掉条件、不以“前10项”截断必要来源。放不下时返回可观测的`required_source_budget_exceeded`，不进入选择调用。该规则在新合成产品和预算边界验证后才允许接线。

只有最终装配的资料进入新的prompt-used和引用映射；被移出项不能再被引用。新增/移出、逐项payload hash、装配版本和结果hash进入新执行身份，**不是追加到旧r8**。题集参考答案仅用于事后评价，不能进入装配器；该资料第8页在原冻结语料内，不需重嵌入、改索引或改检索排序。

## 多维事实合同

新行为名预定`connection_comparison_v1`，仅占用既有内部comparison_answer的显式版本槽；当前尚未注册、启用或切默认。缺省v1、默认关闭及旧v1/v2/v3 proof保持。

| 维度 | 内容 | 不得混同 |
| --- | --- | --- |
| speech_act | 陈述、能力说明、要求、排障指令、条件验证示例、unknown | 排障写法本身不证明或否定连接角色 |
| connection_role | controller_link、client_access、documented_physical_path、explicit_uplink、unknown | 管理用途不是所有业务上联；物理路径不是现场状态 |
| endpoints / medium | 发起端、端口、介质、对端的各自原文跨度 | 不从同文档、标题或另一引用补端点 |
| purpose / qualifiers | 同scope用途、条件、否定、当前版本限制及其跨度 | 不把Web用途迁到Cable，也不删H3C互通限制 |
| operational_status | not_observed、conditional_example、explicit_observation | 手册例子、检查要求不能作为现场观测 |

能力介绍作为独立描述事实，与连接事实分开；“融合Cable与无线路由器”不自动派生无线回程或完整业务路径。scope及字段坐标按Unicode码点，hash按现规范计算；完整原段同时绑定。每条事实还含产品、document/revision/chunk、原件hash、引用号、物理页码或unknown、rule_id和rule_version。当前scope可能含多句话，不能因其中一个否定词把所有独立肯定事实删除；也不能只截取肯定子句而丢掉它自己的条件。

新消费者可独立分析已经核验的完整scope，不能篡改或升级`source_relation_spans_v1`。第一版只准入：明确本机端点的连接句、明确用户到设备的访问句、完整端口—介质—对端的检查句，以及明确单产品主体的融合/客户端能力介绍。缺主语、跨句省略、相对从句、多主体归属或修饰范围不唯一时为unknown；保留原文但不参与强比较。代码/行内代码/HTML属性/图片文字中的伪关系不得成为连接事实。

具体规则必须携带可重算的原文字面依据：同一连接句可直接支持controller_link及其管理用途；同一检查句仅支持documented_physical_path，并保留diagnostic_instruction和not_observed。只有资料原句直接使用上联且语法/否定/端点明确，才产生explicit_uplink。把本机端口到入户接口称作“Cable接入侧路径”属于限定拓扑解释，须标为`qualified_path_interpretation`并同时给出原路径；不得把它无条件升级为explicit_uplink。

## 比较和用户答复

比较器按具体属性与来源角色形成比较项，不要求每个可解释事实都恰好带“上联”二字，也不把两个类别名字不同当成无法回答全部问题。保留三种不同结果：双方同一角色/用途的明确上联可比较介质；两条有来源的对外路径可给出`qualified_medium_difference`，说明各自角色与用途；任一必要事实缺失/冲突则`insufficient`，不能把“不足”当048完整通过。

对限定比较，结论的语义只能是“这两条资料记载的连接介质不同”，不得扩大为所有上联能力不同、两个业务功能相同或现场已接通。3G/4G、3G/4G网络归一为cellular_3g4g；同轴、同轴电缆归一为coaxial；以太网/Ethernet、光纤/fiber沿固定有版本映射。复合/不明介质不得靠相似度猜值。两个同等有效却冲突的事实不能任意择一。

用户端先直接回答，再分别说明两产品的证据及限定，引用贴近所支持的分句。原段放在现有证据视图，不能用长代码摘录替代回答；未知页码保持未知，资料内HTML、图片、指令和编号惰性呈现。比较依据是两个完整事实的并列，不拼接新的端点/介质/用途关系。

048原rubric仍要求LA的3G/4G到AC、CB的Cable与无线路由融合和Cable侧上联/接入比较，以及分型号取证。新设计例子覆盖这几个方面时必须同时保留LA管理用途、CB检查条件、客户端访问边界；不能删用途来强造同层，也不新增“所有答案必须有EoC/GM/GU字样”的门槛。当前总控已写出使用新增冻结概述的完整限定比较草案并审阅7组分句依据；这是设计可行性判断，尚未证明生产程序能稳定生成或通过独立质量复评。

## 证明、恢复与故障

新proof绑定装配输入身份、scope/跨度、规则版本、事实集合、每个比较项的support_fact_ids、覆盖和冲突结果、答案hash，以及原始模型选择（如调用）。完整性由已核验来源依赖和程序规则核对，不能依赖模型恰好选全。非法JSON/截断/重复/来源漂移/预算不足仍先缓冲并拒绝，断流原始选择沿既有同/分库持久化；无静默回退自由答案。
